# ByteBridge

ByteBridge is an independent AZ-900 study companion built with React, TypeScript, Vite, and Express. It includes original practice quizzes, AI-powered concept coaching, flashcards, and progress tracking for Azure Fundamentals learners.

This project is not affiliated with or endorsed by Microsoft.

## Features

- Original beginner-friendly AZ-900 practice quizzes
- Deterministic local quiz scoring and answer validation
- Missed-concept tracking and targeted review flows
- Gemini-powered concept coach on the server side
- Flashcards with review tracking and priority ordering
- Progress dashboard with real learner activity
- Responsive navigation for desktop and mobile
- Local browser storage for progress persistence

## Tech Stack

- React 19
- TypeScript
- Vite
- Express
- Tailwind CSS
- Google GenAI / Gemini
- Firebase-ready telemetry integration

## Prerequisites

- Node.js 18 or newer
- npm
- A valid GEMINI_API_KEY if you want live AI coaching enabled

## Installation

```bash
npm install
```

## Environment setup

Copy the example file and configure the required variables:

```bash
cp .env.example .env
```

Then fill in values such as:

```env
GEMINI_API_KEY="your-key-here"
APP_URL="http://localhost:3000"
```

Important:
- Keep GEMINI_API_KEY on the server side only.
- Do not expose the secret in the browser bundle.
- If no key is configured, the app should still operate with local, catalog-based guidance instead of claiming live Gemini results.

## Notes

- Quiz scoring and progress logic are kept in application logic and are testable independent of the UI.
- Browser storage is accessed behind the app’s data layer to avoid server-side access issues.
- Gemini requests are expected to run on the server for security and correctness.
- The app includes the required study disclaimer and uses original question content rather than real exam questions.

## Deployment

1. Install dependencies.
2. Build the app with `npm run build`.
3. Set `GEMINI_API_KEY` in your deployment environment as a server-side secret.
4. Run the app with the production server command.
5. Ensure `APP_URL` matches your deployed host if needed.
